# W1 — `migrate_running` wired to G3's migrations API

**Status: done.** The AI-agent configurator's `migrate_running` stub is replaced by a real op that calls
`POST /api/platform/workspaces/{ref}/migrations` (docs/G3-API.md §1). A new read op, `migration_status`, covers
`GET …/migrations` and `GET …/migrations/{id}`. Both front doors (CLI + MCP) get them from the shared op registry.
No secrets appear in this report. No services were restarted, and no state-changing git was run.

## What changed (all in `agent-configurator/`, except one audit row)
- **`lib/app-api.mjs`** gains three calls: `migrate(ref, body)`, `listMigrations(ref)` and `getMigration(ref, id)`.
  - **Dry run** (`dry_run: true`): writes nothing in the app, so it is retried like a read on 502/503/504 and on
    transport errors.
  - **Execute** (`dry_run: false`): sent **at most once**. The only retry is on "connection refused", where nothing
    reached the app; this is G1's existing rule for publish. The timeout is 120 s because the app runs one locked
    transaction per site.
  - **Execute failure:** the op reports that the call was "NOT re-sent" and tells the agent to run
    `migration_status` (and a fresh dry run) before trying again.
- **`lib/ops.mjs`:**
  - **`migrate_running`** (destructive):
    - **Defaults:** it is a dry run unless `confirm: true`. Executing also needs a `reason` of 3–500 characters; it
      is checked locally, so nothing is sent without one.
    - **Passed through to the API:** `from_release_version` (N or `"all_older"`), `to_release_version`,
      `scope{module_keys, site_ids, record_ids}`, `stage_map` and `restart_stage_on_chain_change`.
    - **Protected workspaces:** ids in `CFG_PROTECTED_WORKSPACES` can be dry-run but never executed.
    - **Workspace:** a draft-store workspace (id, slug or name), or an app-only configurator ref such as G3's smoke
      workspace, which is not in the draft store.
    - **Result:** a `headline`, `counts` (cases, sites, compatible, blocked, would_migrate or
      migrated/skipped/failed, not_in_flight), one `cases` line per case (site, module, version move, status,
      stage before → after, verdict + blocking reasons, approvals carried, field changes, warning codes), `next`
      hints (confirm + reason; `stage_map` / `restart_stage_on_chain_change` for blocked cases) and the full
      API response as `raw`.
    - **App errors** are mapped:
      - 404 → `not_found`;
      - `unknown_release` → `invalid_input`;
      - 409 → `refused`;
      - 422 (`reason_required`, `same_release`, body) → `invalid_input`.
  - **`migration_status`** (read-only): lists executed runs, newest first (dry runs are never stored). With
    `migration_id` it shows one run with a journal line per moved site pin and case. Each case's full pre-migration
    state is left out unless `include_pre_state: true`.
  - **Server instructions** now describe the loop step and list `migrate_running` among the ops that are dry runs
    unless `confirm: true`.
- **`testkit/fakes.mjs`:** the fake platform API now serves the migrations endpoints with the app's shapes:
  - three cases: one finished, one compatible, one blocked with `stage_missing`;
  - per-workspace history;
  - `extra="forbid"`, `reason_required`, `unknown_release`, `same_release` and `workspace_not_active`;
  - a `migrateFail` switch for 502 / 500 / socket reset.
- **`README.md`:** ops table row, CLI example, retry note, tests line, and 28 tools.
- **`docs/ADOPTION-AUDIT.md`:** only the "Process modelling by API" row changed: 27 → 28 ops, plus
  "+ migrate_running live (…)". A diff confirmed nothing else in the file changed.

## New tests (`test/migrate.test.mjs`)
- **Defaults:**
  - the dry run is the default and sends exactly `{dry_run: true}`;
  - a reason without `confirm` stays a dry run.
- **Execute guards:**
  - `confirm` without a reason (or with one under 3 or over 500 characters) is refused and nothing is sent;
  - schema refusals: a bad `from_release_version`, an unknown scope key, a non-integer `stage_map` value, or a
    `dry_run` argument.
- **Pass-through:** `confirm` + `reason` executes once and passes every argument through unchanged (the reason is
  trimmed).
- **No re-send:**
  - an execute that hits **502** is sent once;
  - an execute whose **connection resets after sending** is sent once;
  - a dry run *is* retried in both of those cases.
- **Errors and access:**
  - app errors are mapped as listed above;
  - a draft-store slug resolves to its id;
  - a protected id can be dry-run, but its execute is refused and nothing is sent.
- **`migration_status`:** list, one run with its journal, pre-state hidden by default, unknown or invalid id, and an
  empty history.
- **Secrets:** no password or admin token appears in any of the 30+ outputs.
- **MCP:** `migrate_running` has `destructiveHint: true`; `migration_status` has `readOnlyHint: true`. A dry run goes
  through MCP, and confirm-without-reason comes back as an `isError` `invalid_input`.

## Notes / limits
- **401 handling:** a 401 on execute still triggers one re-login and one re-send. The app refuses the token before
  doing anything, so this is G1's existing, safe behaviour.
- **What `raw` contains:** the app's migration response includes `actor`, the platform-admin **email** (not the
  password). G1's publish result already outputs that email as `published_by`, so no new exposure was added. The live
  excerpts in this report leave it out.
